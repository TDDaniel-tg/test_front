# test_front

Интерфейс управления картографическими слоями на **React 19 + TypeScript + [vedro](https://www.npmjs.com/package/vedro)**.

## 📌 Описание проекта и требований
Приложение реализует управление картографическими слоями (температура, ветер, инсоляция):
- **Включение / выключение** каждого слоя;
- **Регулировка прозрачности** (`opacity` 0%–100%) в реальном времени с мгновенным отображением на карте;
- **Статусы слоя**: `idle` (ожидание) / `loading` (загрузка) / `success` (готов) / `error` (ошибка);
- **Повторная загрузка (`Retry`)** после ошибки;
- **Имитация API через mock** с настраиваемой задержкой сети и отменой через `AbortSignal`.

## ⚡ Архитектура и решение критериев

### 1. Управление состоянием в Vedro (`src/store/`)
- Хранилище инициализировано через `createVedro<LayersStoreState>()`.
- **Нормализованный стейт**: `layers: Record<LayerId, LayerState>` и `layerIds: LayerId[]`.
- Мутация одного слоя оставляет ссылки всех остальных 99+ слоев неизменными. Встроенный в `vedro` механизм проверки селекторов `isEqual` (`prevCbResult === cbResult || JSON.stringify(...)`) гарантирует, что `setState` вызывается **только** для изменившегося слоя.

### 2. Защита от Race Condition при быстрых переключениях
Двухуровневая защита в `LayerAsyncController` (`src/store/layerManager.ts`):
1. **`AbortController` per Layer**: При быстром переключении (ON → OFF → ON) или повторном клике предыдущий сетевой запрос прерывается через `controller.abort()`. Мок-API слушает `signal` и немедленно прекращает таймер.
2. **Generation Token (Epoch Counter)**: Каждый запрос получает инкрементный токен (`++activeTokens[layerId]`). При ответе проверяется совпадение токена и флаг `layer.enabled`. Устаревшие или отмененные ответы отбрасываются.

### 3. Отсутствие лишних render (Render Optimization)
- Карточки `LayerCard` обернуты в `React.memo` и подписаны только на свой срез `state.layers[id]`.
- Список `LayersList` подписан только на массив `layerIds` — изменение прозрачности или статуса слоя не вызывает перерендер списка.
- На каждой карточке и списке выведен визуальный счетчик **`renders: N`** с flash-подсветкой для наглядной проверки.

### 4. Строгая типизация
- `strict: true`, `noImplicitAny: true`, `strictNullChecks: true`.
- **0% `any`** во всем проекте. Строгие объединения `LayerStatus`, `LayerType`, интерфейсы `LayerState`, `LayerData`.

### 5. Масштабируемость от 3 до 100+ слоев
- В DevTools встроен переключатель: **«3 базовых слоя»** ↔ **«100 слоев (Стресс-тест)»**.
- Нормализация $O(1)$ и мемоизация обеспечивают стабильные **60 FPS** при массовых операциях.

## 🛠️ Запуск проекта

```bash
# Установка зависимостей
npm install

# Запуск dev-сервера (http://localhost:3000)
npm run dev

# Запуск тестов Vitest (11 тестов)
npm test

# Production сборка
npm run build
```

## 🧪 Дополнительные инструменты в UI
- **Live Map Canvas**: визуализация смешивания растров температуры, анимированных стрелок ветра и изолиний инсоляции;
- **DevTools Panel**: слайдер задержки сети, чекбокс принудительного сбоя (503/504), переключатель 100 слоев;
- **Race Condition Spammer**: кнопки автоматического стресс-теста («Спам Toggle ON/OFF», «Спам Retry»);
- **Activity Audit Log**: посекундный журнал токенов, запросов и отмен (`ABORTED`).
